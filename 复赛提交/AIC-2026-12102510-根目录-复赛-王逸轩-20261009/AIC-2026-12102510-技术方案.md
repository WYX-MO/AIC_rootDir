## 一、赛题与评测口径

赛题要求对每条视频给出一个**高光裁剪结果**：一组「保留帧号 + 每帧裁剪框」（框为
目标画幅内的矩形）。评测对每条视频按集合 Dice 计算

```
F1 = 2 · |P ∩ G| / (|P| + |G|)
```

其中 P、G 分别为预测帧集与真值帧集，帧的交集按同帧裁剪框的 IoU 贡献得分，
最后对全部视频宏平均。这一口径有两个直接推论，贯穿了本方案的全部取舍：

1. **帧集是零和博弈**：输出一个真值里没有的帧，只会增大 |P|、拉低 F1；
   反之漏掉一个真值帧则增大 |G|。**选哪些帧**与**框画多准**同等重要。
2. **框准在其次、命中在前**：同帧匹配靠 IoU，只要框大体覆盖主体即可得分；
   真正的难点是「这条视频的高光片段在哪、主体是谁、画幅怎么切」。

因此本方案把问题拆成**时间维**（选帧）与**空间维**（选框）两条正交的线，分别处理。

复赛测试集 426 条，其中 **159 条源画幅等于目标画幅**——此时裁剪框恒等于整幅，
分数 **100% 由选帧决定**；其余 267 条需要挪框，但本地实测预测帧里约 **59%** 在真值
中无对应帧（帧精确率 ≈ 0.41），选帧同样是最大的失分点。

## 二、总体方案

方案在「**全帧保留 + 居中裁剪**」这一稳健基线上，叠加四条互不冲突的改进，全部为
**推理期规则**，不做任何模型训练：

```
视频 →  [时间维] 全帧保留(τ=1，去尾 8%)  −  首/尾黑屏丢帧
     →  [空间维] 自由轴上选框：
             门控(拥挤→居中) / 单主角&宠物→逐帧追踪 / 竖屏→人脸聚焦 / 其余→常数框
     →  VLM 摘要(Qwen2.5-VL-3B)  判定「动物做主角」→ 宠物优先追踪 + 低阈值宠物缓存
     →  predictions.jsonl
```

- **时间维**默认不抽样（τ=1），仅在首/尾识别短时软件的自动片头/片尾黑屏卡并剔除；
- **空间维**沿「自由轴」决定框的位置：横屏源为水平轴 `x`，竖屏源为竖直轴 `y`；
- 唯一参与坐标几何的模型是 **YOLO11n**；**Qwen2.5-VL-3B** 只输出一句中文摘要，
  用于把「动物做主角」的视频挑出来，本身不产生任何坐标。

### 本地 val 消融（57 条，有真值）

| 方案 | val F1 | 说明 |
|---|---|---|
| 居中基线 | 0.3688 | 全帧保留 + 居中裁剪 |
| + 每视频常数红框臂 | 0.4214 | 逐视频主体中心常数（`conf × area` 加权池化中位数） |
| + 杂乱度门控 | 0.4305 | 拥挤视频退回居中（上一版线上冠军） |
| **+ 单主角/宠物逐帧追踪 = 本方案** | **0.4431** | 主体清晰视频改为逐帧移动框 |

追踪分支相对上一版冠军在 val 上 **+0.0126**；线上（`pet.zip`）对应版本得 **35.81**。

## 三、时间维：全帧保留 + 首尾黑屏丢帧

### 3.1 为什么全帧保留
在本赛题上，任何主动抽样（保留分数高的前 p 分位）都劣于「一个不丢」：抽样的取舍在
val 上是净负，`keep_all` 恒为最优。故基线保留全部帧，只去掉末尾 8%（`drop-tail 0.08`，
规避片尾黑场与演职员表），即保留帧集 `0 … ceil(0.92n) − 1`。

### 3.2 首/尾黑屏片头片尾丢帧
短视频软件（VIDEVO / 抖音等）常给视频自动加上片头/片尾卡：画面大部分是黑或深灰、
**且没有主体**。这类帧若照常输出框，等于「预测了真值没有的帧」，按 F1 直接失分。
故在**开头或结尾**满足下述两个条件的连续帧，从帧集里**剔除**：

1. **画面足够黑**：暗像素占比（灰度 < 60 的像素比例）≥ **0.80**，且整帧灰度均值 ≤ **60**；
2. **确无主体**：该帧没有 `conf ≥ 0.30` 的 person / cat / dog 目标。

**两个条件缺一不可**，这是本规则鲁棒的关键：

- 纯夜戏（如某条视频灰度均值仅 8.5、99% 像素为黑）**确有 person 检出**，故不会被误丢；
- 纯黑帧上 YOLO 会产生**虚假检出**（把噪声报成 person / 其他类），若只看「黑」不看
  「是否有目标」会误伤真实内容，因此"无目标"一侧必须存在。

实现上 `black_cache.py` 只负责把「每抽样帧有多黑」（灰度均值 + 暗像素占比，stride=5，
与 YOLO 缓存对齐）量出来存成缓存，**判不判、丢多少**由 `emit_trace.py` 的阈值参数决定，
换阈值无需重新解码。为防止极端情况整条视频被丢空，另加 `--max-drop 0.5` 上限保护。

> 该规则是**线上导向**的：本地 val 的 57 条里没有软件片头片尾，因此 val 上丢帧数为 0、
> 分数不变；它只在复赛测试集上生效（426 条中 71 条命中，共丢 3844 帧）。

## 四、空间维：门控 / 追踪 / 人脸 / 常数框

沿自由轴（`stage_data.free_axis`：横屏源 `x`、竖屏源 `y`、源=目标则恒定整幅）逐视频
决定输出框。所有主体中心都按 **`conf × area` 加权池化**逐抽样帧求出，再插值到逐帧。

### 4.1 门控回退（拥挤 → 居中）
逐帧 person 检出的**均值超过绝对阈值 2.0** 的视频，判为「拥挤、中心无意义」，
回退为居中裁剪。用**绝对刻度**而非分位数：线上测试集的拥挤度只有本地 val 的一半，
分位数阈值会随分布漂移，绝对阈值更稳。

### 4.2 单主角 / 宠物 逐帧追踪
上一版的红框臂是**每视频一个常数中心**，在**全部**视频上测得的逐帧跟踪是**净负**
（Δ −0.0099）——因为多主体视频里「多个近似并列的物体来回翻」导致框抖动。但这一负结论
被多主体视频主导；**单主角视频**没有这个抖动问题，逐帧信息应当干净。于是新增一条分支：
对「主体检出稳定、单主角」且**未被门控**的视频，把每抽样帧的主体中心插值到逐帧、
再做时序平滑（`--smooth 15`），得到**逐帧移动**的裁剪框。

- **宠物优先**：当 VLM 摘要判定该视频「动物做主角」（见第五节）时，主体一律判为
  cat/dog，**即便画面中同时有 person**——否则「小狗在主人身后跑」这类视频会把中心让给
  主人、聚焦错对象。宠物视频一律走逐帧追踪，不受单主角占比门槛限制。
- **低阈值宠物缓存**：主缓存是 `conf=0.25` 全类检出；中远景奔跑的小猫小狗常因低于该
  阈值直接丢检，导致逐帧追踪「无中心可插值」。故 `pet_cache.py` 对动物主语视频单独跑
  一遍 `classes=cat/dog, conf≈0.05` 的低阈值缓存，`emit_trace` 对这类视频改读它。

### 4.3 竖屏人脸聚焦
竖屏源 → 16:9 目标时，裁剪窗只能**上下平移**（自由轴 = `y`）。旧口径取 person 框中心
= 胸腰位置，视觉上偏下。改用

```
cy = y_top + 0.24 · h_box      (f = 0.24)
```

把焦点抬到「脸—胸口之间」（0.10 偏额头、0.20 偏脸、0.24 脸-胸口、>0.30 开始切头）。
这需要 person 框的**框顶**与**框高**，而主缓存只存了 `cx/cy/area`，故 `face_cache.py`
对竖屏视频单独跑一遍 person 检测并**保留整框几何**（`top`、`bh`），供上式使用。

### 4.4 常数框（兜底）
多主体但不拥挤、且未被上述分支接管的视频，沿用上一版的**每视频常数红框**。

## 五、动物主角判定（VLM 摘要）

`vlm_summary.py` 用 **Qwen2.5-VL-3B-Instruct** 对每条视频抽样 8 帧、生成一句不超过 15 字
的中文摘要；摘要命中「猫 / 狗 / 柯基 / 犬 / 猫咪 / 小狗 / 猫猫 / 狗狗 / 宠物 / 金毛 /
泰迪 / 柴犬 / 哈士奇 / 边牧 / 萨摩 / 田园犬」等词条，即判该视频为**动物做主角**。
这一判定同时驱动两件事：4.2 节的**宠物优先追踪**与 **0.05 低阈值宠物缓存**；两处词条
口径在 `pet_cache.py` 与 `emit_trace.py` 中完全一致。

VLM 的角色被刻意限制为「判别器」而非「回归器」：在本地 val 上，直接让 3B 模型做
**时间区间定位 + 空间重构**的基线显著劣于「什么都不做」的全帧居中对冲（模型往往回答
"整段都是高光"），故本方案**不采用** VLM 的区间/坐标输出，只用它的一句摘要来做**离散
判定**——这是 3B 模型在 8 GB 显存下唯一被验证为可靠的用法。

## 六、模型与 `model_size_mb`

| 权重 | 大小（原始/解压后） | 用途 |
|---|---|---|
| `yolo11n.pt` | 5,520,527 B ≈ 5.26 MB | 逐帧检测，提供全部坐标几何 |
| `Qwen/Qwen2.5-VL-3B-Instruct` | 7,509,337,976 B ≈ 7161.46 MB | 视频摘要（离散判定「动物主角」） |

合计 **7,514,858,503 B ≈ 7166.73 MB**，低于 9 GB 上限。预测文件每行
`model_size_mb = 7166.73`（口径 = 推理实际加载的全部模型权重、解压后总大小）。
VLM 推理时以 4-bit（bitsandbytes NF4）**加载**以适配 8 GB 显存，填报仍按原始权重文件
大小计算。除上述两个权重外无 Adapter / LoRA / 分割 / 跟踪模型。

## 八、小结

- **时间维**：全帧保留（τ=1）为最强先验；唯一例外是首/尾的软件片头片尾黑屏卡，
  用「大部分黑灰 **且** 无目标」的双条件判据剔除，避免误伤夜间真内容。
- **空间维**：门控回退 + 单主角/宠物逐帧追踪 + 竖屏人脸聚焦 + 常数框兜底，
  以自由轴为唯一决策尺度；val 上相对上一版冠军 +0.0126。
- **VLM**：仅作「动物主角」离散判别，驱动宠物优先与低阈值缓存；不做区间/坐标回归。
- **模型**：只用 YOLO11n + Qwen2.5-VL-3B，共 7166.73 MB，无训练。
